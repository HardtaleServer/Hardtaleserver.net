What was fixed

1) Grants idempotency index startup conflict (P0)
- Startup index creation for `grants.idempotencyKey` now matches existing sparse index shape:
  - key: `{ idempotencyKey: 1 }`
  - options: `{ unique: true, sparse: true, name: "idempotencyKey_1" }`
- Added safe guard for Mongo error code 86 (`IndexKeySpecsConflict`):
  - logs one warning
  - continues startup
  - does NOT brick Mongo readiness / API startup.

2) /api/server/* auth-before-readiness hygiene
- Route flow was reordered so server auth check runs before DB readiness checks on server routes.
- This avoids exposing DB-up/down differences to unauthenticated callers.

3) Health/readiness observability
- `/health` now includes explicit `mongoReady` and sanitized Mongo readiness snapshot.
- `/health/ready` returns:
  - 200 when ready
  - 503 when not ready
- Snapshot is sanitized and intentionally boring (no URI/host/user/secrets).

4) Optional fail-fast startup mode
- Added `WAIT_FOR_MONGO_BEFORE_LISTEN=true` support:
  - when enabled, app waits for Mongo ready before binding HTTP listener.
  - useful in prod if you prefer fail-fast readiness semantics.

5) Legacy fulfillment endpoint protection
- Legacy `/api/fulfillment/*` endpoints remain shimmed to canonical grants lane handlers and are protected by same server secret auth path.

6) Plugin backoff policy doc added
- `plugin-backoff-policy.txt` created with:
  - transient handling (500/502/503/timeouts)
  - exponential backoff + jitter
  - logging hygiene (no secrets)
  - recommended poll intervals.
